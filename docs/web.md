# OHI — веб-приложение (`web/`)

Flask-приложение для мониторинга и модерации СМИ: просмотр собранных новостей,
поиск по темам/ключевым словам, управление источниками (RSS-лентами),
аналитика, служебные логи и параметры фоновых сервисов. Часть монорепозитория
`D:\demidov_sun\OHI` (рядом — `server/`, фоновый сборщик новостей, и `shared/`
— код, общий для web и server).

Точка входа — `web/main_ohi_web.py`. Деплой — Google Cloud Run
(`web/Dockerfile`, `.github/workflows/deploy-web.yml`).

## Архитектура

- **Данные приложение не хранит само** — все запросы к БД/бизнес-логике идут
  через REST API отдельного сервера (`common.send_rest`, авторизация через
  `common.login_admin`/токен пользователя). Flask-приложение — тонкий UI-слой
  поверх этого API.
- **Состояние пользователя — серверная сессия в памяти**, не Flask-`session`
  напрямую: `users_session.py` (`class Session`) держит словарь
  `{user_id: {...}}` (тема, язык интерфейса, часовой пояс, права, текущие
  фильтры форм и т.п.), периодически сериализуется в `static/session.json`.
  Экземпляр `users_session.users` создаётся один раз при старте процесса —
  при перезапуске (новый деплой) все сессии сбрасываются.
- **Каждая страница** реализована связкой: `main_ohi_web.py` (роут) →
  `<page>.py` (`prepare_form(user_id, request[, ...])`, вся логика: чтение
  форм, вызовы REST, подготовка `answer`/`par` для шаблона) →
  `templates/<page>.html` (+ иногда собственный `static/css/<page>.css` и
  `static/js/<page>.js`).
- **Навигация** — общий `templates/include/menu2.html`: закреплённая слева
  боковая панель (сворачивается, ширина тянется мышью, состояние — в
  `localStorage`) + верхняя топбар-панель (гамбургер, хлебные крошки текущего
  раздела, select языка интерфейса, кнопка темы). Подключается либо через
  `base.html` (большинство страниц), либо напрямую (несколько самостоятельных
  HTML-документов — см. ниже).
- **Тема оформления** (чёрная/белая) переключается мгновенно на клиенте
  (`static/js/theme_switch.js`, `localStorage`), без перезагрузки страницы;
  на сервер синхронизируется отдельным лёгким POST
  (`/api/set_theme/<user_id>/`) или попутно с любым обычным сабмитом формы
  (скрытое поле `select_theme_form`, `common.choose_language`). Цвета текущей
  темы — `colors.py` (`colors['white']`/`colors['black']`), передаются в
  шаблоны как `colors`.
- **Локализация интерфейса** — `language.py`. Для каждой страницы — свой
  список строк-констант на русском (`language.menu`, `language.log`,
  `language.news_board`, ...); `language.get_lang(user_id, 'форма', массив)`
  при первом обращении к языку, которого ещё нет в кеше, переводит весь
  список через Google Translate (`deep_translator`) и сохраняет результат в
  `static/language.json` (дальше отдаётся из кеша). Список языков —
  `config.languages` (ru/en/he/de/fr/es/zh-CN). Устойчиво к сбоям перевода:
  при ошибке конкретной строки используется русский оригинал, а не всё
  обнуляется (см. `language.py:_is_bad_translation`,
  `new.py:_looks_like_refusal` — аналогичная защита от отказов ChatGPT).
- Часть страниц — **AJAX-формы** (полная перерисовка без перезагрузки:
  `guests`, `functions`, `news_board`), часть — **классические
  POST-формы** с перезагрузкой страницы (`rss`, `search_words`, `logs`,
  `new`, `analyses`). Индикатор загрузки — общий `#loadingIcon`
  (`.loading-icon`, вращающаяся иконка `static/waiting.png`).

## Аутентификация и доступ

- `login.py` + `templates/login.html` — вход по имени/паролю
  (`common.make_login`), определение часового пояса по времени браузера,
  права (`admin`/`visible`) читаются из БД. После входа наполняется `upr`
  (user preferences: имя, id, права, тема, цвета, часовой пояс, язык) —
  этот словарь передаётся почти во все шаблоны.
- `common.init_form(user_id, request, endpoint)` — общая проверка "пользователь
  всё ещё существует в сессии"; если нет — редирект на `/login/` с
  запоминанием, куда вернуться (`page_for_return`).
- `one_new/<new_id>/` — вход в обход обычной формы логина, по одноразовой
  ссылке из Telegram-бота (`common.user_from_chat`): определяет пользователя
  по данным чата, открывает конкретную новость модально на странице
  `news_board`.
- `delete_unit.py` + `templates/delete_unit.html` — общее межстраничное
  диалоговое окно подтверждения удаления (тема/RSS-лента/новость — тип
  задаётся заранее через сессию, `get(user_id, 'delete_source')`).

## Страницы

### Новости (дашборд) — `news_board.py` / `templates/news_board.html`
Главная страница: таблица новостей за выбранные сутки (фильтры — канал,
тема, поиск по тексту, сортировка), полностью на AJAX
(`static/js/news_board.js`): смена даты/дальнейшая работа со списком не
перезагружает страницу — `/api/news_board/<user_id>/data`. Особенности:
- Просмотр/редактирование новости — **модальное окно** (`#nbm_modal`), а не
  переход на отдельную страницу; переиспользует ту же логику, что и
  `/new/` (`/api/new_board/<user_id>/<new_id>/` — JSON-обёртка над
  `new.py:prepare_form`).
- Выбранная новость запоминается (`localStorage`) и выделяется фоном
  постоянно, при любой перерисовке таблицы; кнопка "перейти к новости по
  ID" (`/api/news_board/<user_id>/find/<news_id>`) находит нужные сутки и
  прокручивает к строке.
- Открытие новости по ссылке из чат-бота (`?open_id=`) и возврат из статьи,
  открытой в отдельной вкладке (`?select_id=`), обрабатываются на клиенте.
- Удаление новости — только для админов (`/api/news_board/.../delete/<id>`).
- Интерфейс полностью локализован (`language.news_board`, 47 строк).

### Новость — `new.py` / `templates/new.html`
Просмотр и редактирование одной новости (заголовок/описание — на выбранном
языке, полный текст статьи). Действия: сохранить, отменить несохранённые
изменения, перевести на RU/EN/EN/HE через ChatGPT (`translate()` — OpenAI
API, с защитой от отказа модели переводить), заново прочитать статью с
исходного сайта (`article_parser.py` — эвристический парсер JSON-LD/DOM),
подгрузить исходный (непереведённый) файл из облака. Все действия
логируются (`common.write_log_db`) с диффом изменений
(`common.what_change`). Полный текст статьи хранится не в БД, а в Google
Cloud Storage (`cloud.py`, бакет `llm_news`, `.txt`/`.7z`).

### Посетители сайта — `guests.py` / `templates/guests.html`
Статистика визитов (гости сайта) — списком и по посещённым страницам,
с фильтром по датам/поиском, диаграммой (Chart.js) и постраничным выводом.
AJAX (`/api/guests/<user_id>/data`).

### Новостные ленты — `rss.py` / `templates/rss.html`
Справочник источников (RSS-лент): список + правая панель редактирования
(создание/правка/удаление ленты, тип ленты, язык, описание). Классическая
форма (перезагрузка страницы).

### Поисковые образы — `search_words.py` / `templates/search_words/`
Управление "темами" (поисковыми образами — наборами ключевых слов/фраз,
по которым фоновый сервер ищет совпадения в новостях). Три режима:
подробности по теме (список найденных новостей + текст с подсветкой
совпадений, плагин `highlightWithinTextarea`), диаграмма по датам,
служебный режим (администрирование самих тем).

### Лог работы / Лог чата — `logs.py`, `chat_logs.py`
Просмотр журнала событий (`logs`) и переписки Telegram-бота (`chat_logs`) —
таблицы с фильтрами по дате/тексту, постраничный вывод. `logs` — общий
журнал всего приложения (см. "Логирование" ниже).

### Параметры сервисов — `functions.py` / `templates/functions.html`
Администрирование конфигурационных параметров фоновых потоков сервера
(периоды опроса, ключи API и т.п. — то, что `server/trafaret_thread.py`
подгружает через `load_config_params`). AJAX-форма, только для админов.

### Аналитика — `analyses.py` / `templates/analyses.html`
Самостоятельный HTML-документ (не наследует `base.html` — свой Bootstrap 5,
свои копии CSS-переменных темы и `#loadingIcon`). Графики (Plotly) по
каналам/темам за период: количество сообщений, разбивка по неделям/дням,
произвольный или относительный период (7/30/90/180/365 дней или весь
период с 2000 года). POST/Redirect/GET после отправки формы — чтобы
Ctrl+F5 не повторял сдвиг периода.

## Общие модули

- **`common.py`** — самый крупный модуль: обёртка над REST API
  (`send_rest`), сессия пользователя (`get`/`add` — тонкие обёртки над
  `users_session.users`), логирование (`write_log`, `write_log_db`),
  авторизация чата (`user_from_chat`, `fix_login`), геолокация гостя по IP
  (`define_guest`, `get_timezone_minutes_by_ip`), работа с датами и часовыми
  поясами (`get_date_sql`, `convert_time_to_timezone`), сравнение
  объектов для логов (`what_change`). Часть функций (`decode`/`encode`/
  `str1000`/`get_duration`) вынесена в `shared/ohi_shared/text_utils.py` —
  байт-в-байт одинаковый код, раньше дублировался в web и server.
- **`cloud.py`** — Google Cloud Storage (бакет `llm_news`): загрузка/запись
  текстов статей (`.txt`, при необходимости `.7z`), удаление файлов новости
  при её удалении.
- **`article_parser.py`** — эвристический парсер полного текста статьи по
  URL (JSON-LD `NewsArticle` → fallback по DOM-селекторам), используется
  кнопкой "Статья" на форме `new`.
- **`language.py`** — см. "Локализация интерфейса" выше.
- **`colors.py`** — палитры цветов для тёмной/светлой темы.
- **`config.py`** — переменные окружения (`.env`): порт, URL REST API,
  ключ шифрования, список языков интерфейса.
- **`users_session.py`** — хранилище сессий пользователей в памяти процесса.

## Логирование

Единый журнал событий (таблица `logs` в БД, просматривается на странице
"Лог работы") — `common.write_log_db(level, source, message, ...)`.
Используется повсеместно: вход пользователей (`USER`), обращения к ChatGPT
и ошибки/отказы перевода (`ChatGPT`/`ChatGPT-Exception`), действия на форме
`new` (сохранение, отмена, смена языка, обновление статьи, загрузка файла),
изменения справочников (RSS-лент, функций/параметров), внутренние ошибки
500 (`ERROR-500`, глобальный `@app.errorhandler(500)`), старт процесса
(`START WEB`).
